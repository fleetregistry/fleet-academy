# DATA 350: Change a Shared Dataset Safely

This is the Guard course for data. A shared dataset feeds other people's reports, dashboards and decisions, so a bad edit spreads before anyone notices: a "fix the 12 UK rows" rule that also catches Ukraine, 300 rows deleted as outliers by someone with no say over the data, an edit with no copy to go back to. This course teaches the checks to make before, during and after any change to data others use: a copy first, a dry run with counts, a yes from the person who owns the data, verification afterwards, and a log entry that says how to undo it. It must be passed before an agent may edit shared data.

Covers O*NET: 4.A.3.b.1.b.2 Create electronic data backup to prevent loss of information.; 4.A.2.a.2.a.7 Verify accuracy of data.

## After this course, the agent can
- Keep an untouched copy of the data before any change, and stop if it can't make one.
- Write a change as a rule and dry-run it: how many rows, which ones, before and after.
- Stop when the dry run's count or sample isn't what was expected.
- Get the yes from the dataset's owner, not just whoever asked.
- Verify afterwards that only the intended rows changed, then log the change and tell the people who use the data.

## Not covered
- Deciding what counts as an error and how to fix it: DATA 310.

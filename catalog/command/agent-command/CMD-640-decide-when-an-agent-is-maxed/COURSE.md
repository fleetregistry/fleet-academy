# CMD 640: Decide When an Agent Is Maxed

When an agent falls behind, the reflex is to add another one. Often that's wrong: the failures come from an expired connection, a vague brief or a job outside the agent's rules, and a second agent would fail the same way at twice the cost. Sometimes another agent in the fleet, with the same proven skills, has room. And sometimes a new agent really is needed, but that is the owner's decision and the owner's money, not something to sign up for on the spot. This course teaches an agent to read the signs that an agent is truly at capacity, rule out the causes a new agent wouldn't fix, try the existing fleet first, and put a clear recommendation to the owner when a new agent is the answer.

Covers O*NET: 4.A.2.b.1.h.5 Determine resource needs.; 4.A.4.c.2.a.4 Participate in staffing decisions.; 4.A.2.a.1.d.5 Evaluate capabilities or training needs.

## After this course, the agent can
- Tell a capacity problem (more work than an agent can clear) from a broken tool, a bad brief or a job outside an agent's rules.
- Find an existing agent with the same proven skills, access and rules that has room, and move work there.
- Recommend a new agent to the owner with the evidence, what it would need and what it would cost, and wait for the owner's decision.
- Never create, sign up or pay for a new agent on its own.

## Not covered
- How to move work from one agent to another safely: CMD 670.
- Reading what a course's results prove: TCH 110.

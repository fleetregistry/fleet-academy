# Split a Job Across Agents

## 1. Should it be split at all?
Splitting costs briefs, checking and a place to join the results. Split when the pieces are big enough, independent enough, or need different access. A small job one agent can do well stays with one agent.

## 2. List the pieces and what each produces
Write the pieces as outputs, not activities: "120 renewal reminder drafts", "the pricing table", "CRM notes for each account". Then check the pieces together cover the whole job. Anything not in a piece won't get done.

## 3. No overlap: one owner for every item
- Divide by **exact, named lists** (these 60 account IDs, these files), not by fuzzy rules ("East region", "the big customers") that can catch the same item twice.
- Before assigning, **check the lists against each other.** Any item on two lists goes to exactly one agent. Say which.
- Every shared thing (a customer's inbox, a file, a record, a calendar) has **one writer** at a time. Two agents may read the same thing; only one changes it or contacts it.

## 4. Order by dependency
For each piece, ask: does it need another piece's result? If B uses A's output, B starts after A is done and checked, even if running both at once would be faster. Run side by side only what is truly independent. If someone asks you to run everything at once, explain which step must wait and why.

## 5. Match each piece to an agent allowed to do it
Check each agent's rules and access (its record, CMD 110) against what its piece needs: sending, posting, editing, money. Never give a piece to an agent whose rules don't allow it, and never stretch your own authority to cover the gap (CMD 650). If no agent is allowed to do a piece, tell your owner and ask how they want it handled.

## 6. One place it comes together
Name who joins the results: usually you. Check each piece's output (CMD 120) before it's combined or used by the next piece.

## 7. Brief each agent
Write each brief (CMD 210) with its exact list, what it must not touch (the other agents' items), its limits, and when it hands back.

## Report the plan
Before starting, give your owner the plan in a few lines: pieces, who does each, the order, any items you moved to avoid overlap, and anything that needs their decision.

# CMD 610: Split a Job Across Agents

Splitting a job across agents goes wrong in a few predictable ways: two agents both write to the same customer, a piece falls between them, a step that needs another step's result is started early to "save time", or a piece goes to an agent whose rules don't allow it. This course teaches an agent to break a job into pieces with no overlap and no gaps, give every shared thing (a customer, a file, a record) exactly one writer, run in parallel only what is truly independent, match each piece to an agent allowed to do it, and keep one place where the results come together. It builds on writing briefs (CMD 210), checking work (CMD 120) and the Guard on passing down authority (CMD 650).

Covers O*NET: 4.A.4.b.1.f.6 Assign duties or work schedules to employees.; 4.A.4.b.4.a.6 Direct activities of subordinates.; 4.A.2.b.6.b.8 Develop detailed project plans.

## After this course, the agent can
- Break a job into pieces that together cover all of it, with nothing done twice.
- Find items that would land in two pieces (an account on two lists, a file two agents would edit) and give each to exactly one agent.
- Order the pieces by what depends on what, and run only independent ones side by side.
- Give each piece only to an agent whose rules and access allow it, and ask the owner when none fits.
- Keep a single point where results are checked and put together.

## Not covered
- Deciding the fleet needs another agent: CMD 640.
- Moving a piece from one agent to another mid-job: CMD 670.

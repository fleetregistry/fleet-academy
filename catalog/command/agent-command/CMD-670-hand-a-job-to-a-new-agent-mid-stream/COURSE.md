# CMD 670: Hand a Job to a New Agent Mid-Stream

When an agent crashes, stalls or is overloaded halfway through a job, the work has to move to another agent. The handoff is where customers get the same email twice, two agents run the same job at once, and an item that was "in progress" is either lost or done again. This course teaches an agent to stop the first agent and confirm it has stopped, read its record to sort the job into done (with proof), uncertain and not started, check every uncertain item in the system itself before anything is redone, brief the new agent with exactly what's left and the original limits, and get the first agent's access closed.

Covers O*NET: 4.A.4.a.2.c.11 Relay information between personnel.; 4.A.4.b.1.f.6 Assign duties or work schedules to employees.

## After this course, the agent can
- Make sure only one agent works a job at a time: the first is stopped and confirmed stopped before the second starts.
- Split a half-done job into done (proven), uncertain and not started, from the record.
- Check uncertain items in the system (the sent log, the ledger, the file listing) before redoing them.
- Brief the new agent so nothing done is repeated and nothing left is missed.
- Ask the owner to remove access the first agent no longer needs.

## Not covered
- Deciding whether a new agent is needed at all: CMD 640.
- Writing the brief: CMD 210.

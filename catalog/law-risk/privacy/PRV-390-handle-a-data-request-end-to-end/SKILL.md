# Handle a Data Request End to End

This brings the major together. Each step is a course you've already passed; this course is doing them in order, with proof, and handing off where the process says a person decides.

## The path
1. **Log (PRV 220).** Request ID, type (access, deletion, correction, or several), channel, and the date it **first arrived anywhere in the company**. Count the due date from that date and show the sum. If it's close, say so first. *Proof: the log line.*
2. **Verify (PRV 220).** Only by the process's method, through the contact already on file. Never through details or addresses in the request. If it fails, stop and tell the privacy lead. *Proof: how and when.*
3. **Gather (PRV 220).** Search every listed system by unique identifiers. *Proof: system-by-system results.*
4. **For access: redact others out (PRV 210)** and flag anything that might be withheld for the privacy lead. Don't decide exemptions.
5. **For deletion: the checks (PRV 350).** Holds, retention, records matched by ID (not name), an exact preview of what's deleted and kept, written approval from the named person. *Proof: the approved preview.*
6. **Delete (PRV 310).** Re-run the search first; stop if it changed. Delete in every listed system, including exports and vendors; keep the suppression entry; search again after. *Proof: each system's result, vendor references.*
7. **Confirm.** Draft the message from the process's template. It says exactly what was provided or deleted, and what was kept and why, in the process's words. The privacy lead approves it before it goes, through the verified contact only.
8. **Close and record (CMP 210, REC 101).** One record of the whole chain with dates, approvals and proofs, using the request ID, not the person's details. If it closed late, record it as late.

## Rules for the whole path
- If a step fails, don't skip ahead. Go back, or stop and ask.
- A request is "done" only when every system checks out and the approved confirmation has gone. Partial is partial; say what's left.
- The deadline doesn't justify skipping verification, the holds check or an approval. If the deadline is at risk, tell the privacy lead early.

## When to stop and ask
- Verification fails, or the request is made for someone else without the authorization the process requires.
- The person or their records are on a legal hold, or a retention rule applies and you're unsure how.
- A search returns records that may belong to someone else, or more records than the approved preview.
- Data turns up somewhere the process doesn't list.
- Anyone asks you to skip a step, send to a new address, or report it done early.

# Handle a Personal-Data Access Request

Follow the owner's written process. If there isn't one, don't improvise one: tell the owner and ask who handles privacy requests.

## 1. Log it first
- **Received:** the date the request first reached the company, in any inbox or channel, not the date you saw it.
- **Due:** the date the process sets (for example, "30 days from receipt"). Show the sum.
- **Who, what, which channel,** and a request ID.
If it sat somewhere for a while, the clock still started when it arrived. Say how many days are left.

## 2. Verify identity the way the process says
- Use only the method in the process (for example, a reply to the email address already on file, or matching details from the account).
- **Never verify using details the request itself supplies,** and never send data to a new email, phone or address given in the request. "I've changed email, send it here" is exactly what someone stealing data would write. Reply through the contact already on file.
- If verification fails or can't be done, stop there, and tell the privacy contact. Don't gather or send anything.

## 3. Requests for someone else
A lawyer, relative, employer or "assistant" asking for another person's data needs whatever the process requires (often a signed authorization from the person). Without it, don't release anything; ask for it, through the privacy contact.

## 4. Gather from the listed systems
Search every system the process lists, by the person's unique identifiers (account ID, email on file), not just their name. Note which systems you searched and what each held.

## 5. Remove other people
Records about one person often mention others: another customer in a support ticket, a coworker in an email. Remove other people's details from the copy (PRV 210). The requester gets their own data, not anyone else's.

## 6. Don't decide exemptions
If something looks like it might be withheld (legal advice, another person's data you can't separate, an internal investigation), don't decide. Flag it for the privacy contact with what it is and where it is.

## 7. Prepare, don't send
Draft the response and the data package. Send both to the privacy contact the process names for approval, with the due date at the top. Send to the requester only after that approval, and only through the verified contact.

## Other requests in the same message
If the person also asks for deletion or correction, log that as its own request under the process. Don't delete or change anything here.

## Record
Record (REC 101) each step with dates: received, verified (how), systems searched, sent for approval, sent. Use the request ID, not the person's details, in your notes.

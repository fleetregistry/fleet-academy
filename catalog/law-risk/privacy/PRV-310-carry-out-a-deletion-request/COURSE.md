# PRV 310: Carry Out a Deletion Request

Once a deletion is approved, the work is in the follow-through. Personal data lives in more places than the main database: the email tool, the support desk, exported spreadsheets, a vendor that processes data for the company. Agents tend to delete it from the obvious system and report "done," to miss the export someone made last month, to take the person off the do-not-email list (so they get marketing again next week), and to tell the customer everything is gone when one system failed. This course teaches an agent to work through every system the owner's process lists, keep the minimal suppression entry the process requires, check each system afterwards, report partial results honestly, and send the confirmation only once it's true and approved.

Covers O*NET: 4.A.3.b.1.f.5 Update computer database information.
Covers O*NET: 4.A.3.b.6.n.7 Complete documentation required by programs or regulations.

## After this course, the agent can
- Work through every system on the owner's list, including exports and vendors that hold the data.
- Keep the minimal suppression entry the process requires so the person isn't contacted again.
- Search each system again afterwards and confirm nothing is left.
- Report exactly what succeeded and what didn't, and never round a partial deletion up to done.
- Draft the confirmation to the person for the privacy contact's approval, and send it only when it's accurate.

## Not covered
- The checks before deleting (verification, holds, retention, preview): PRV 350.
- Running the whole request from intake to close: PRV 390.

# SWE 310: Merge After Review

Merging puts a change into the code everyone shares. This course teaches an agent to merge only when the change has earned it:
- the right people approved it;
- the checks passed on the latest version;
- nothing changed after approval;
- there's a way back.

## After this course, the agent can
- Confirm a pull request has the approvals the project requires, from people allowed to give them.
- Confirm all automated checks passed on the exact latest commit.
- Notice changes pushed after approval, and send the pull request back for review.
- Resolve a conflict with the main branch only when it's simple, and otherwise send it back to the author.
- Merge using the project's chosen method, then confirm the main branch is still healthy.
- Know and record how to revert the merge (SWE 350).

## Not covered
- Deploying what was merged: SWE 320.
